# Buying the two VPNs

Mullvad and OVPN were checked against their own pages on 2026-10-24, Surfshark on 2026-10-26. Prices change. The field names below do not: they are the lines inside a WireGuard file, plus one address that is not in that file.

Buy these from a machine other than the bridge. Do not install either provider's app on the bridge. The bridge only gets the tokens in the last section.

Pay the two hops with different instruments. The same card, PayPal account, or email links them even when the tunnels do not. Mullvad can be paid with cash or Monero and does not require an email. Use that for hop 1 if you can.

## Hop 1: Mullvad

This hop does not need a dedicated address. One shared Mullvad server is enough.

1. Open https://mullvad.net/en/account/create and generate an account. Mullvad shows a numeric account number. That number is the login. Write it down somewhere that is not the bridge.
2. Pay at the account page. The price on https://mullvad.net/en/pricing is €5 per month, including VAT, whether you buy one month or longer. They accept cash, Bitcoin, Bitcoin Cash, Monero, bank wire, credit card, PayPal, Swish, Eps, Bancontact, iDEAL | Wero, and Przelewy24. Cryptocurrency is discounted 10% on that page. Cash uses a payment token from their site, mailed with the cash. A 14-day refund exists, except for cash.
3. On the same machine, generate a keypair. Do not let Mullvad generate the private key.

```sh
wg genkey | tee mullvad.private | wg pubkey > mullvad.public
chmod 600 mullvad.private
```

4. Log in with the account number and add one device by pasting `mullvad.public` only. Then open https://mullvad.net/en/account/wireguard-config?platform=linux and download one server, for example a Sweden server. Do not enable Mullvad Multihop. Do not enable Mullvad's kill switch. Both fight the layout in [README.md](README.md).
5. Open the downloaded file, named like `se-mma-wg-001.conf`. If `PrivateKey` is already filled, Mullvad generated it. Delete that download and repeat from step 3. `PrivateKey` must be empty, or absent, so you can fill it from `mullvad.private`.

One Mullvad account allows 5 devices. This bridge is one device. Do not reuse this key on another machine.

## Hop 2: Surfshark, with a Dedicated IP

This is the address Cloudflare, the explorer, and the Solana RPC see. Surfshark is the default because it is the provider from the common list that gives all three of the following; most give only one or two:

1. A WireGuard configuration file you can run with `wg-quick` on a server with no screen. Not an app, and not an OpenVPN file.
2. A dedicated IPv4 address that works through that file. A shared server address changes, is shared with other customers, and gets rate-limited at public APIs.
3. A way to register a public key you generated yourself, so the provider never holds the private key. If a provider only generates the pair for you and shows the private key once, it still works; it is one notch weaker.

| Provider | WireGuard file for Linux | Your own key | Dedicated address through that file | Verdict |
| --- | --- | --- | --- | --- |
| Surfshark | Yes | Yes, "I have a key pair" | Yes, one per account, as a WireGuard download from the Dedicated IP settings | Works. Steps below |
| OVPN | Yes | Yes | Yes, the Public IPv4 add-on. Commercial use needs their approval first | Works. Ask support before paying, pick a city with stock |
| Mullvad | Yes | Yes | No dedicated addresses | Hop 1 only |
| Proton VPN | Yes, generated by Proton | No, Proton generates the pair | Not on consumer plans | Hop 1 only, if you accept the generated key |
| NordVPN | No. Manual files are OpenVPN and IKEv2; its WireGuard needs the NordVPN app | – | – | Not usable here |
| ExpressVPN | No. Manual files are OpenVPN only | – | – | Not usable here |
| CyberGhost | Not verified | – | Not verified | Check their dashboard offers a WireGuard file for the dedicated address before paying |

The table is a snapshot. If you choose a provider other than Surfshark, confirm in its dashboard that the dedicated address has a WireGuard download, not only OpenVPN, before paying.

### Surfshark

1. Create an account at https://surfshark.com and pay for a plan with an instrument that is not the one used for hop 1 or Cloudflare.
2. Buy a Dedicated IP from the Dedicated IP order page in the dashboard. Surfshark allows one per account. Pick a city in a different country from the house.
3. Generate the hop 2 key on the same non-bridge machine:

```sh
wg genkey | tee hop2.private | wg pubkey > hop2.public
chmod 600 hop2.private
```

4. In the dashboard open **VPN** > **Manual setup** > **Desktop or mobile** > **WireGuard**, choose **I have a key pair**, name it, and paste `hop2.public`. Do not choose **I don't have a key pair**; that makes Surfshark generate the private key.
5. In the **Dedicated IP** section open **Settings**, pick **WireGuard**, and download the configuration file. The pop-up shows the dedicated address and the key you registered. Surfshark's own page: https://support.surfshark.com/hc/en-us/articles/10760833967506
6. Open the downloaded file. `PrivateKey` is empty or absent, because Surfshark does not have it; you fill it from `hop2.private`. Copy `Address`, `DNS`, `PublicKey`, and `Endpoint` from the file.
7. The dedicated address shown in the Dedicated IP settings is `VPN_PUBLIC_IPV4`. It is not one of the lines in the file.

### Any other provider that passes the table

The installer does not know provider names. Whatever you buy, fill the same seven `VPN_` lines from its WireGuard file and `VPN_PUBLIC_IPV4` from its dedicated-address page. After the tunnel is up, the installer refuses to continue unless the machine's traffic really leaves from `VPN_PUBLIC_IPV4`, so a wrong address or a shared server is caught before anything is built.

## What the installer accepts

Copy [params.conf.example](../../params.conf.example) to a path outside this repository. Fill only these tokens. The installer does not get the Mullvad account number, the hop 2 username or password, or either private-key file left in Downloads.

| Installer token | Where it comes from |
| --- | --- |
| `HOP1_PROVIDER` | `mullvad`. A label; it does not switch hop 1 on |
| `HOP1_WG_PRIVATE_KEY` | `mullvad.private`, also the `PrivateKey` line under `[Interface]` |
| `HOP1_WG_ADDRESS` | `Address` under `[Interface]` in the Mullvad file |
| `HOP1_WG_DNS` | `DNS` under `[Interface]` in the Mullvad file |
| `HOP1_WG_PEER_PUBLIC_KEY` | `PublicKey` under `[Peer]` in the Mullvad file |
| `HOP1_WG_ENDPOINT` | `Endpoint` under `[Peer]` in the Mullvad file |
| `HOP1_WG_ALLOWED_IPS` | `0.0.0.0/0, ::/0` |
| `VPN_PROVIDER` | `surfshark`, or the name of the provider you chose instead. A label |
| `VPN_WG_PRIVATE_KEY` | `hop2.private`, also the `PrivateKey` line under `[Interface]` |
| `VPN_WG_ADDRESS` | `Address` under `[Interface]` in the hop 2 file |
| `VPN_WG_DNS` | `DNS` under `[Interface]` in the hop 2 file |
| `VPN_WG_PEER_PUBLIC_KEY` | `PublicKey` under `[Peer]` in the hop 2 file |
| `VPN_WG_ENDPOINT` | `Endpoint` under `[Peer]` in the hop 2 file |
| `VPN_WG_ALLOWED_IPS` | `0.0.0.0/0, ::/0` |
| `VPN_PUBLIC_IPV4` | The dedicated address shown on the provider's dedicated-IP page. Not a line in the WireGuard file |
| `CLOUDFLARE_TUNNEL_TOKEN` | The `eyJ...` string from [cloudflare.md](cloudflare.md). Not the install command |
| `CLOUDFLARE_HOSTNAME` | The published name from [cloudflare.md](cloudflare.md). Not `swap.beta.ecash.com` |

Leave the six `HOP1_WG_` lines empty if you are using Surfshark alone; `HOP1_PROVIDER` is only a label. One VPN is enough to hide the house from Cloudflare. It is not enough to hide the house from Surfshark.

After the tokens are in the outside file, delete `mullvad.private`, `hop2.private`, and both downloaded `.conf` files from the machine you used to buy the accounts. Keep the Mullvad account number and the hop 2 login somewhere you can reach without the bridge. You need them to renew, and to replace a config if a server is retired. You do not need them to run the bridge.
